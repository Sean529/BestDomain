### 核心架构图
**用户/程序** $\rightarrow$ **DNSPod（优选 IP 记录）** $\rightarrow$ **Cloudflare 边缘节点** $\rightarrow$ **Cloud Connector (Host 重写)** $\rightarrow$ **AWS S3 (源站)**

---

### 方案各层级拆解

#### 1. 解析层：动态优选 IP (DNSPod + GitHub Actions)
*   **痛点**：Cloudflare 的默认分配 IP 在国内部分网络环境下速度慢，甚至可能因解析泄露直连源站（导致之前的 `ConnectTimeoutError`）。
*   **解决**：
    *   利用 GitHub Actions 每小时从 `IPDB` 库拉取中国电信、联通、移动最快的 **Cloudflare 官方 IP**。
    *   通过 API 自动将优选结果更新到 **DNSPod (腾讯云)** 的 A 记录。
*   **结果**：强制流量从最快的“高速公路入口”进入 Cloudflare 内部网络，彻底杜绝了直连 AWS S3。

#### 2. 接入层：Cloudflare for SaaS (自定义主机名)
*   **功能**：让托管在腾讯云的域名 `cdn.hiyinni.com` 也能享受 Cloudflare 的全套功能（WAF、缓存、SSL）。
*   **SSL 验证**：通过 `_acme-challenge` 的 CNAME 委派，实现了证书的 **一次配置，终身自动续期**。

#### 3. 转换层：Cloud Connector (回源优化)
*   **痛点**：AWS S3 对回源请求的 `Host` 标头有严格要求，不匹配会报 403。同时，S3 的新加坡/印尼节点在国内直接访问非常不稳定。
*   **解决**：
    *   使用 Cloudflare 最新的 **Cloud Connector** 功能，自动将进入节点的请求 Host 修改为 S3 的长域名。
    *   由 Cloudflare 的国际骨干网去连接 S3 节点，绕过了公网的抖动。
*   **结果**：彻底解决了连接超时和 403 拒绝访问的问题。

#### 4. 存储层：AWS S3
*   **功能**：作为文件源站，提供高可靠的数据存储。由于前端有 Cloudflare 挡着，S3 的流量费和请求费也会因为缓存而大大降低。

---

### 为什么这套方案是“无敌”的？

1.  **极速连接**：通过 IP 优选，解决了 Cloudflare 在国内的“减速”问题。
2.  **彻底降费**：利用 Cloudflare 缓存，减少了 AWS S3 的高昂下行流量费用。
3.  **全自动维护**：
    *   **IP 自动更新**：GitHub 脚本每小时自动换 IP。
    *   **证书自动续期**：Cloudflare 自动管理 SSL 证书。
4.  **高可用性**：即便某个 Cloudflare IP 被墙，GitHub Actions 也会在下一小时自动将其替换为可用的优质 IP。

### 日常维护建议（只需看一眼）

*   **检查 Actions 状态**：偶尔看看 GitHub 的 Actions 页面有没有报红（通常是由于 Secret 密钥失效或网络抖动）。
*   **观察解析记录**：在腾讯云后台，如果看到 `cdn` 记录是一堆 A 记录且在变动，说明系统运行完美。
*   **缓存刷新**：如果你更新了 S3 里的音频文件但域名没生效，记得在 Cloudflare 后台点一下“清除缓存 (Purge Cache)”。
